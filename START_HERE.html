GAMEREACH · 0.11.0

少翻一些资讯，
更快找到想玩的游戏。

先把你的兴趣理解清楚，再从可核对的游戏资料里寻找候选。这里保留一条集中的探索路径，让玩法、优点和取舍更容易看懂。

本地运行 默认离线演示 桌面 / 手机布局

先启动，再打开页面

  1. 解压整个项目。需要 Python 3.11+；首次安装依赖需要网络。
  2. Windows：双击 Start_GameReach.bat。macOS / Linux：在项目目录执行 bash scripts/run_demo.sh。
  3. 看到服务启动后，保留终端窗口，点击下面的入口。
打开 GameReach →

这是使用说明页；完整功能由本地服务提供。包内已带构建后的前端与字体，直接体验无需 Node.js。停止服务按 Ctrl+C。

01

理解你的兴趣

在“我的游戏资料”导入游戏库或文件。挑选真正代表你的游戏，排除挂机和其实不喜欢的体验。阅读并修改兴趣评价，再确认加入探索。

02

找到可比较的候选

描述这次想玩的感觉；可附加多张兴趣卡片，原输入保持独立。商店和运行平台支持多选，默认全部。开始探索后，可先解析并编辑玩法标签、方向、重要度与软硬条件，确认后再寻找候选。

03

看懂玩法与取舍

先读“怎么玩”和优缺点，再看合拍之处。感兴趣就保存到清单，或去商店看玩法展示。想核对时点击文字旁边的来源。

第一次体验：5 分钟路线

  1. 保留默认演示模式，进入“我的游戏资料”，载入虚构游戏库示例。
  2. 也可导入 data/fixtures/v011_player_library.json，整理两种重叠主题；编辑成员与概括后确认。
  3. 使用一张兴趣卡片，再补一句这次不想接受的体验。
  4. 选择平台，开始探索。查看一段介绍和它的原文依据。
  5. 点击“感兴趣”；在清单里留下吸引你的原因。之后整理兴趣会参考这些线索。

演示中的 24 款游戏、评论和公告全部虚构。真实数据与真实模型需要各自开启，不能只看“真实模型”标识就认定游戏来源也是真实的。

【需你填写】只在接入真实服务时

在 .env 配置 IGDB Client ID / Secret 和模型 Base URL / API Key / Model；导入 Steam 个人库时另填 Steam Web API Key。网页里只填你的 SteamID64 或数字主页链接，不要把主页链接填进密钥字段。

修改后重启后端。详细步骤见 接入说明；新检索功能无需新增密钥。

怎样知道模型和游戏资料是真实的？

同时设置 DATA_MODE=live 与 LLM_MODE=live。模式标识只是配置状态，还要看任务中实际调用与错误记录，并打开证据核对真实来源、时间和原文。缓存命中可不新增请求；未知信息会保留，不会用演示内容补上。

已有项目如何升级

停止旧服务并备份数据库，在新目录解压本版本，再复制原来的 .env 和 data/gamereach.db。启动会补建索引。不要把旧源码整体合并回来，以免重新带入已删除的模块。

兴趣卡片、游戏资料和历史报告保留；本次没有SQL表/列迁移，提供只写新路径的备份与恢复脚本。详见升级与回退说明。

以玩家体验标签寻找证据

本版使用64个标签，覆盖操作、构筑、重复与刷取、失败、探索、叙事、合作、生存等体验。商店标签只用于召回，模型必须读取完整评价并逐项核验后才能形成匹配证据。没有提及不等于没有。

排序围绕本次关注点：未知软偏好不当作负面，已核验匹配和冲突决定排序。硬条件未知仍待确认；展开可查看完整证据与诊断。

真实完整评价接口目前是Steam，其他商店经IGDB目录召回；没有冒充已经抓取所有论坛。本轮后端279项、前端10项和Chromium桌面/窄屏30项通过；真实模型与外部数据服务未执行验收。
