# GameReach 空结果问题：分析清单与 v0.9.1 修复

这次问题不应归结为“偏好太严格”或“这些游戏不符合需求”。截图中的第 5 项 Elden Ring 标记为“待调查”，完整阅读和获取评价均为 0；这说明它尚未获得可用于判断的评价数据。v0.9.0 却用完整推荐卡和 0% 覆盖率展示它，混淆了“没做调查”和“不匹配”。这是上一版实现的缺陷。

检查日期：2026-10-21。依据：你提供的截图、v0.9.0 源码、故障回归、Steam 官方文档和实际匿名接口检查。没有取得你当时那次任务的 JSON、数据库或运行日志，所以不能把截图之外所有空卡的具体触发原因断言为同一问题。

## 2. 如何判断一张卡为什么没有数据

在新版展开“待调查或证据不足的目录候选”，依次看：

1. **本轮未安排调查**：只被召回，不是失败，也不是不匹配。默认预算通常优先处理 3 款。
2. **缺少可用的评价接口或 Steam ID**：当前无法取得玩家评价，目录标签不能代替证据。
3. **获取 0 篇且有来源错误**：查 `investigations[game_id].get_reviews` 和 `errors`；需要解决连接、限流或响应问题。
4. **获取大于 0，全文分析为 0**：查模型调用、全局停止原因、正文长度。不能将下载量当阅读量。
5. **全文分析大于 0，提取为 0**：查 `findings_returned`、`findings_accepted`、`extraction_rejections`。没有相关语义和引用被拒绝是两种原因。
6. **提取大于 0，核验支持为 0**：查核验错误、rejected/insufficient 和逐项 verification。未驳回不等于通过。
7. **核验支持大于 0，标签匹配未知**：查是否属于无关主张、已失效来源或场景限定；展开具体引用。
8. **已有支持但仍待确认**：查看明确必要条件、事实范围或相反证据，不能仅按总分判断。

新版 JSON 入口：结果页“JSON”。重点字段为 `query`、`interpretation`、`diagnostics`、`investigations`、`stop_reason`、`model_protocol_errors`、`results[].diagnosis`、`reading_ledger`。原任务仍保留原快照，升级不会悄悄改写历史结论。

## 3. 修复后的实际流程

- LLM 先分析输入和主动附加的兴趣卡片，再检索目录。
- 仅把当前可获得完整评价的候选安排进自动深入调查。
- 每款：获取详情与评价 → 完整正文分析 → 引用定位校验 → 独立语义核验 → 保存结果。
- 单款提取/核验故障不阻塞后续游戏；全局预算耗尽则停止并保留已核验结果。
- 最后按已有证据排序。未调查、未核验和只有窄场景证据的候选单独说明。
- 人工研究/核验模式保留原有一次审阅节点，因此不能承诺与全自动模式完全相同的逐款交错顺序。

这次没有通过增大预算、降低核验要求、虚构评价或给未知项填默认分来制造“正常卡片”。现有权重仍是初始工程方案；本次没有做真实用户推荐质量实验。

- 错误列表为空。统计是检查时的快照，不代表未来不变；20 篇样本的赞踩比例不用于总体评分。
- 机器可读记录：`docs/STEAM_SMOKE_091.json`。未调用真实 LLM，也未验证 IGDB→LLM 的完整真实推荐质量。

- [IUserReviewsService / GetAppReviews](https://partner.steamgames.com/doc/webapi/IUserReviewsService?l=english)：新接口、input_json、purchase_type 枚举、总体统计返回条件。

## 5. 升级与复核

1. 停止旧服务，备份原 `data/gamereach.db` 与 `.env`。
2. 在新目录解压 v0.9.1；复制原 `.env` 和数据库到相同相对位置。若 DATABASE_URL 指向其他位置，保留其实际配置。
3. 使用 `Start_GameReach.bat`（Windows）或 `bash scripts/run_demo.sh`（macOS/Linux）启动。确认侧栏和 `/healthz` 显示 0.9.1，再刷新页面。
4. 用同一段需求**重新探索**。旧任务不会自动重跑，升级无法补造它当时没有取得的证据。无需删除旧历史或密钥。
5. 可单独检查公开评论接口：进入 backend，运行 `uv run python ../scripts/check_steam_reviews.py --appid 1245620`。这只打印统计，不调用模型、不输出评论作者或正文。
6. 若新任务仍没有推荐，查看逐款诊断及 JSON。它应准确告诉你哪个阶段没有产出，而不再给出一整页看似经过评分的空卡。
