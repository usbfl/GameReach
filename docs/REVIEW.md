# 0.7 审查与纠正记录

本轮以附件《GameReach：RAG 接入核对记录与实施要点》和“准确分析兴趣、高效搜索游戏”为边界，审查源码、数据库迁移、来源与模型链路、页面、依赖、配置、测试、启动与交付文档。没有读取或公布用户密钥，没有清空用户数据库。

## 纠正的准确性与效率问题

- 原文后半段玩法容易漏读，且核验器也只读开头：改为检索片段和引文附近窗口。
- 旧版本 / 撤销来源仍可能参与画像：当前评估重新检查来源有效性；旧源不再制造与新版本的假冲突。
- 相同引文重复出现时可能定位到未提供给模型的位置：仅在实际片段范围内查找精确偏移。
- 索引重建可能无法恢复丢失的块：完整重建可重新分块，保留撤销 / 权限状态；启动采用增量检查。
- 旧偏好可能覆盖这次输入：当前文本与显式字段优先，历史只填空白。
- 反馈与探索的解析不一致，负向描述可能成为正向偏好：统一解析器并补回归。
- 真实 Planner 返回的软兴趣可能因提前生成 DNA 查询而被忽略：允许补充未识别维度，不能改写已识别要求或新增硬限制。
- 进入关注页会搜索真实目录：改为只读本地游戏，新增兴趣不抓公告。
- 人工规划候选依赖另一个页面加载、人工阅读只露出原文前段：改为本地任务候选与按需展开完整原文。
- 无资料却继续调用相同来源：使用已返回的评论游标和既有补查上限；未知保持未知，不循环重试相同动作。

## 有意保留

人工接管、任务历史、错误与未知说明、配置检查、预算与证据抽屉虽然不属于主卡片内容，但对准确性、可控调用和问题排查必要。它们收在按需展开的操作中，不另建主流程。

“语义支持”仍必须逐项核验：精确引文存在不证明结论正确。真实玩家喜好、论坛来源覆盖、实际购买地区与价格，都不能用离线合成测试替代。本轮没有新增论坛抓取或用游戏名编造介绍。

## 0.8 · 完整推荐与真实验证（2026-10-20）

本轮只修正搜索结果质量、证据充分性和卡片可读性，没有新增独立研究流程。

确认的原因：目录候选与完成调查的推荐混排；下载评论数被当作阅读量；12片段容易被少数长差评占满；默认模式被模型写成任意 scope 名称；核验器过度要求官方证据；另一方面，模型又常把引用外的信息塞进单条主张；IGDB 发售状态缺失；“牌组构筑”与关键词拼写遗漏，以及空评价量记录靠前造成召回偏离。

纠正：统一发布准入、分层采样与阅读台账、默认 scope 归一、带限制的体验注明适用条件、机制主张按词表值生成单一命题再独立核验、一次本地修订、Steam 商店来源与发售核对、关键词同义拼写和有评价量目录优先召回。真实研究角色只接收当前批次游戏，不夹带其他候选的资料缺口。候选召回只决定调查顺序，不作为机制或适配度的证据。

未完成候选留在快照以便局部重排，但所有对外推荐结果都重新执行准入；已知不符合必要条件时停止继续采集。价格、未识别限制、未知机制仍不能自动通过。没有可靠缺点就暂缓，不生成填充文本。

项目未加入论坛爬虫、账号管理或额外模型服务。实际体验评价仍来自Steam，新增商店说明和目录资料用于交叉核对，明确区分玩家意见与发行商说明。
