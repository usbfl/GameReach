### 兴趣与时长

明确 `dislike` / `exclude` 的游戏权重为0且不能新归入正向主题。其他状态基础关注权重：入库1、收藏/关注1.5、明确喜欢2；采用语义层级，不把喜欢、收藏、关注相加。时长加成是 `0.25 × min(log(1+hours)/log(51), 1)`，50小时饱和；没有时长仍有基础权重，1000小时不压过明确喜欢。权重表达关注强度，不等同喜欢程度或推荐证据。

每个主题内按游戏身份去重；画像从唯一游戏集合计算，卡片重叠不增加同一游戏对同标签的贡献。已核验 DNA 当前只自动投影 `build_diversity → build_variety`；难度高不能推断必须读招，策略深不能推断回合制。其他已有 DNA 不补查，后续可增加经过语义审查的投影。

默认 `INTEREST_MIN_GAMES=3`、`INTEREST_MAX_GAMES=7`、`INTEREST_MAX_CARDS=6`。允许最少2–7、最多3–12、卡数1–12，且最大不得小于最小。默认资料不足不凑数。配置改变会使相应缓存失效。任务附加卡片上限仍为原来的6。

重复整理复用不变资料；改变一个主题独有成员不会使另一个主题失效。已确认卡片不随生成重写。手动选入的成员标为用户编辑，不伪装目录归类。旧文本卡片可读可编辑，可补充真实已有成员。

### 需求、优先级及未映射表达

新 `POST /api/tag-intent-preview` 使用既有解析器；mock为规则，live为配置模型，不调用候选目录或库存评论。输入/附件变更后预览无效。研究请求的 `confirmed_conditions` 是完整最终快照，删除的标签不会从原文或历史重新注入；支持合法正式ID和任务级自定义表达。已确认平台条件不会被原文没有PC字样而清除。

“不太喜欢刷装备”是软避开，“绝对不能要求刷装备”才是硬避开。同义表达复用已有ID，未映射片段保留供编辑或忽略。自定义表达没有可靠目录/评论映射时不参与自动打分；硬自定义条件保留unknown，因此不能进入已确认满足组。没有自动扩写全球词表。

卡片是辅助输入，同标签不按卡片数累加。当前明确输入覆盖冲突的历史推断；最终人工确认覆盖自动解释。用户仍可跳过预览直接自动研究。

### 排序公式

仅考虑本次标签、同适用范围、有效来源且已独立核验的完整评价主张。对每个标签，以独立作者/正文去重后的支持与反对计算 `m = 支持/(支持+反对)`；没有相关证据为unknown。

- `M`：仅已知标签的优先级加权平均 m。
- `K`：已核验标签的重要度总和。
- `Q`：每标签最多3位独立支持者的饱和数量，按已知标签权重平均。
- `C`：已知标签的 `priority × (1-m)` 之和。
- `R`：平台总体口碑 Wilson 下界；缺失取排序中性先验0.5，界面仍显示未知。

`score = clamp(15 + 40×(2M−1) + 30×min(K/6,1) + 10Q + 5R − 25×min(C/3,1), 0, 100)`。

K=0时无分数。未知不进入分母，不伪造支持。只验证一个重要度1的次要项，即便支持充分且口碑极高，最多75分；已核验更多重要维度会得到额外但有限的奖励。coverage、已核验/未知维度数继续保留，coverage不乘进分数。分数是工程排序信号，未经真实用户实验校准，不是满意概率。

硬条件与分数独立：已证实失败排除；未知待确认；冲突证据无法消解时也待确认。硬条件均通过且存在本次正向支持时可推荐部分匹配；没有所有软偏好的证据不再强制 provisional。明确软冲突保留在取舍组并扣分，不因为分数低就伪造硬排除。

### 研究与停止

保留原 Planner/Researcher/Verifier 结构。首先沿用事实约束筛选，玩法补查优先硬条件，再查本次最高重要度的未知/冲突。只有一位独立声音或现有差评尚未覆盖时保留平衡检查；重要证据已够、不再有可行动核心缺口时停止，次要未知继续显示在展开面板。

当前平台/语言等事实未知不会用更多评论“补成”已满足，也没有新增外部事实数据源。初次提取可以产生同批其他当前标签证据，但不会为与任务无关的20项机制发起调查。缺介绍/口碑不单独阻止有来源的偏好匹配。

### 缓存与成本

保留快速/均衡/扩大、广召回窄调查、每批全文上限、来源TTL、模型/工具/时间预算。核验缓存忽略纯priority与确认标记，仍包含标签/方向/范围、硬条件、自定义需求、数据集、文档哈希和协议版本等。单纯本地重排不调用模型或外部工具；新增关注点与硬约束不会无条件复用不适用结论。升级协议导致首次核验缓存未命中是有意失效，不是历史丢失。

## 保留、未新增与局限

- 保留现有API默认协议、旧DNA和报告、持久化任务、暂停/恢复/人工审阅、来源定位、导出、库导入与个人清单。
- 本阶段未做库存逐款评论研究、自动正式标签创建、多模型路由、服务商自动切换、精确人民币费用。
- 目录线索有噪声；规则主题去重是保守启发式，对复杂语义近似的live输出不保证完美。用户可编辑；下一步可增加带标注的主题一致性评估。
- 自动解析（尤其否定的作用域、多子句硬条件）仍需更大真实语料验证；编辑确认提供明确控制，不宣称自然语言解析全覆盖。
- 未映射自定义软需求仅保留和提示，尚无通用检索/证据抽取；可映射到正式标签后研究，或将硬条件保持待确认。
- TTL/版本有效不等于游戏更新后事实永远不变；真实证据新鲜度和提供商返回仍需线上监测。
- 本次未跑真实LLM/IGDB/Steam端到端，不声称节省付费金额或提升真实玩家满意度。详见验收报告。
