# v0.11 离线实验与新旧对照

**实验类型：固定合成数据 + 离线规则；不是真实模型、真实游戏或玩家满意度实验。**

使用当前实际Engine、数据库、来源/核验和排序路径，fixtures/mock；外部请求和LLM调用都为0。可重复执行：`cd backend && uv run python ../scripts/verify_v011.py`。脚本使用临时DB、不依赖现有用户资料。随机任务ID/时间戳可变化，游戏、评论、条件与断言固定。实际完整输出在 `validation_v011/offline_experiments.json`，19通过、0失败。

## 案例一：重叠画像

输入 `data/fixtures/v011_player_library.json`：A具有构筑和反复挑战，B/C为构筑，D/E为反复挑战；A/C无时长；B收藏；E明确喜欢；F有60,000分钟但明确exclude。

| 主题 | 实际成员 | 结果 |
|---|---|---|
| 构筑改变打法 | A、B、C | 3个唯一成员 |
| 练习攻克Boss | A、D、E | 3个唯一成员 |
| 排除游戏F | 无 | 高时长未使其返回正向组 |

主题依据标为用户分类，不冒充社区核验。A跨主题共享，画像每主题只计一次；旧算法只能形成1张、3个游戏—主题关系，新算法2张、6个关系。重复整理命中缓存、复用2卡、处理新增游戏0，模型/工具/外部请求均0。

## 案例二：少量关注点与大量未知

实际生成 fx-02 合成候选证据，然后用同一证据快照添加20个无关未知字段。新分数79.17→79.17，旧分数84.17→84.17；两者都没有因为完全无关未知降级，新方案不申请补查。该项是维持正确行为，不是声称修复了旧版所有无关未知问题。

再增加优先级1“快速重试”软偏好，构筑优先级3且有两条已核验证据：新版仍79.17、`group=recommended`、`partial_match=true`，快速重试 `match=null`；已核验1维、未知1维。旧分数从84.17降至65.0，揭示coverage乘法带来的软未知扣分。

新版推荐只声称已证实的构筑变化，不声称快速重试成立。没有为另外20项机制追加研究。完整来源和字符位置保留。

## 验证边界

合成证据独立编写并由既有fixture注释核验，实际执行了核验/引用定位/缓存路径；未调用真实LLM判语义。这些实验证明确定性行为与协议，不证明线上召回覆盖或真实语义准确率。没有为了比较而预设新版所有指标更好。
