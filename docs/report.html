实际验收结果

检查项记录结果主要覆盖
后端 pytest279 通过兴趣重叠、条件优先级、硬条件未知、引用、状态兼容

数据库兼容8 检查通过旧版合成数据库升级与回退
TypeScript / Vite / Ruff通过类型、生产构建及后端静态检查

各组检查存在覆盖重叠，不能相加当作独立实验场景数。

值得核对的行为

  • 游戏可以进入多个不同主题，但同一张兴趣卡内不会重复。
  • 明确不喜欢或排除的反馈优先于高游玩时长。
  • 最终人工编辑条件优先；没有证据的硬条件不会被当作满足。
  • 未知软偏好不作负面判定；无关玩法不会触发无意义补查。
  • 单纯调整重要度可复用已有证据，本地重排不新增研究请求。

边界与证据

真实 LLM / IGDB / Steam 端到端、Windows / macOS 实机、Docker 运行及真实用户数据库未在本版验收。真实推荐质量与金额节省尚未测量。
