# GameReach v0.10.2：预算节省方案已实现

本版落实缓存与增量整理、快速试探、广召回后集中调查、按证据缺口追加。默认使用“均衡精选”。暂不做分级模型、服务商切换、价格计算或真实付费调用；原有模型配置和预算上限保持不变。

## 现在如何使用

1. 在研究输入下选择“快速探索 / 均衡精选 / 扩大调查”，再设置期望推荐数量1–10款。
2. 重复整理兴趣时，自动复用未变化的分组；新增或变化的游戏单独整理。若希望新游戏参与全部重新分类，勾选“全部重新分组”。
3. 报告中展开“本轮预算策略”，查看来源缓存命中、复用全文批次、追加调查和停止原因。只调整既有标签的重要度时，继续使用已有报告的本地重排功能，无需重新研究。

## 已落实的方案

| 方案 | 当前行为 | 保留的边界 |
|---|---|---|
| 来源缓存 | 目录与详情默认缓存6小时，评价30分钟；正常缓存命中不重复外部获取 | 工具动作仍计数。部分获取失败不写成功缓存；缓存不是实时数据 |
| 兴趣增量整理 | 对游戏来源、资料、理由和输入语境计算指纹；资料相同直接复用，未变化的3–7款分组保持稳定 | 不自动改写旧卡片。剩余不足3款时保留待归类，可手动选择全部重分组 |
| 已核验批次复用 | 相同需求解释与完整来源批次可以跨任务复用，重新校验引用和来源可用性，并保留原任务编号 | 需求、正文、作用域、数据集、模型配置或协议变化会失效；过期、撤销和核验失败不能直接复用 |
| 快速试探 | 快速档减少目录扫描、调查数量和每款批次 | 可少于期望推荐数量，不凑数 |
| 广召回、窄调查 | 多页目录先本地去重排序，当前输入优先；相关度相同的候选兼顾不同标签线索。初筛后先调查一小组，未达目标逐款递补 | 平台标签仍然只是召回依据，不算玩家体验证据；不将整个目录送入模型 |
| 按缺口追加 | 优先补主要需求、明确要求、冲突意见、玩法介绍和独立观点；没有可补资料、无新增有效证据或需保留后续预算时停止 | 保持完整正文、好评/差评/近期分层与独立核验；未知不转为满足 |

所有档位都使用现有模型和核验协议。缓存复用是在程序中跳过已经完成且仍有效的工作，没有增加模型路由。

## 三个档位的默认范围

| 档位 | 目录扫描上限 | 初筛名单上限 | 首轮安排 | 总调查上限 | 每款批次上限 |
|---|---:|---:|---:|---:|---:|
| 快速探索 | 150条 | 20款 | 3款 | 3款 | 1批 |
| 均衡精选，默认 | 500条 | 30款 | 5款 | max(5, 目标数×2)，最多20款 | 3批 |
| 扩大调查 | 500条 | 80款 | 5款 | 20款 | 3批 |

表中都是上限，环境配置可以进一步收紧。目录记录不等于不同游戏数量；分支检索结果会去重。已有预算不足时，实际调查数会更低；达到目标时立即停止后续候选。报告区分“已达到目标，主动停止”与“失败或预算不足”。

均衡档先为后续候选留出请求预算，避免一直围绕第一款补查。扩大档允许优先为当前重要缺口追加，但同样不能突破预算。首轮没有达到目标时才递补候选；失败不会使后续候选自动失败。

## 何时继续读评论，何时停止

追加的理由包括：主要需求尚未知、存在相反观点、缺乏有来源的玩法介绍、尚无偏好支持、只有一位独立玩家，或已有差评样本尚未阅读。

选评保留完整正文，对重复作者和重复文本去重，优先选择与缺口有关的未读资料，保留反对与近期分层。关键词只用于选择下一批材料，最终结论仍须引用和核验。

以下情况停止追加，并在报告保留原因：

- 卡片和主要需求已有证据，剩余只是次要未知项。
- 可用未读正文没有与当前缺口有关的线索，或独立全文放不进批次上限。
- 追加一批后没有新的有效证据。
- 已达档位批次上限，或需要为下一款保留预算。
- 已有明确反证导致排除，或完整卡片已达到本次目标。

平台总体口碑、语言或商店事实缺失，不会通过不停读评论来假装补齐。评价未提及某项体验，仍不代表该体验不存在。

## 缓存的有效期与失效规则

新增设置均有默认值，无需修改现有配置即可使用：

```dotenv
REUSE_ENABLED=true
REUSE_TTL_SECONDS=86400
SOURCE_CATALOG_TTL_SECONDS=21600
SOURCE_DETAILS_TTL_SECONDS=21600
SOURCE_REVIEWS_TTL_SECONDS=1800
```

`REUSE_ENABLED=false` 关闭兴趣整理和已核验批次的语义结果复用；普通来源缓存仍遵循独立的来源有效期。修改有效期后，旧配置对应的缓存不继续当作新配置的命中。

每个缓存类别在写入时清理过期记录并限制最多200项。清理的是可再生成的缓存，不是用户游戏、卡片、历史报告或原文证据；没有新增数据库表。

已核验结果复用采取保守规则：本次完整需求解释必须一致。更改需求、标签优先级或来源引用后，重新发起的研究可能不命中旧批次；仅调整排序重要度可使用本地重排。人工研究/核验流程继续经过人工节点，不用自动缓存替代人工决策。旧版任务没有生成这种缓存，升级后的首次研究通常需要完整处理。

## 仍未达到或尚未验证

1. 尚未实测真实平台上的节省比例、等待时间、冷门作品召回率和推荐质量；不能承诺每轮都能形成1–10张完整推荐卡片。
2. 模型分级、价格配置与费用估算暂未实现，按本次要求后置。
3. 不同语义需求之间只要解释不同，就不会直接复用整批结论；更细的逐条主张增量复用暂未启用。
4. 关键词选评可能遗漏没有使用相关词语的有效评论；当前策略是有限、可解释的启发式，不是穷尽搜索。
5. 新增或变化游戏不足3款时不能单独生成分组；全部重新分组能重新分配成员，但不保证所有游戏都有足够共同资料。
6. 本版未新增论坛采集器；实际完整评价来源仍遵循现有Steam适配范围。
7. 浏览器视觉与交互验收仍需在安装Chromium的环境执行。
