## 2. “未完成调查”具体指什么

原任务中17款只完成目录召回，未抓取评论；另3款已取得正文，停在提取，715篇不能算“已完成全文分析”，也没有已经通过核验的结论。未调查不等于不匹配。

新版每款保留来源获取状态、提交给模型的文档ID、已完成分析的全文范围/哈希、合法/拒绝主张、核验状态、缺失偏好和停止原因。`unfinished_investigations`是尚未成为精选结果的调查清单；`reading.deferred`是获取但未完成分析的评价数。已提交但失败的尝试记在`model_requests`，不会假装形成了可靠结论。

## 3. 本版实际修改

- 新流程默认扫描最多500条目录记录，含跨查询重复；去重、按范围过滤和当前意愿排序后保留80款，逐款调查上限20款。原有MAX_CANDIDATES与MAX_DEEP_RESEARCH_GAMES不再限制新标签流程。
- 界面支持期望1–10款。达到目标或预算/候选用尽后输出实际结果，不用待调查游戏凑数，也不声称全市场最优。
- 每款默认获取36篇完整评论，按好评/差评/近期分层；每批最多4篇、16,000字符，可附加完整简介；主要证据缺失时最多追加至3批。超长正文延期，不截断当全文。
- 提取只允许本次需求标签；aspect与tag_id关联规则和scope键写进schema。单条坏结果隔离，超量主张有界保留；完全无法解析时最多一次带错误反馈的JSON模式重试。
- 本次真实试跑还暴露了超量findings、工具参数JSON编码错误、泛指PC被复制为每项体验限定、无关标签消耗输出名额。均已针对性修正；平台版本确有差异的限定仍保留。
- 只有“避开什么”的证据、没有任何当前想要玩法的支持时列为待确认。核心玩法、理由、取舍、口碑、来源及未知声明构成卡片；“卡片结构完整”不代表所有偏好都已证实。
- 每个批次核验结果立即保存。后续失败保留成果；下一款预算明显不足时停止，避免只抓正文却没有分析预算。
- 报告新增目标达成数、分页记录、错误明细、恢复记录和未完成清单。旧报告保留原状，不改写历史。

## 5. 需要你做什么

1. 停止旧服务，把新版解压到一个新目录；先保留旧目录作为回退，不直接覆盖运行中的程序。
2. 将原项目根目录`.env`复制到新项目根目录。不要用`.env.example`覆盖你的密钥配置；这份包不附带真实env。
3. 如需保留历史、个人库与卡片，在旧服务停止后复制数据库到新配置指向的位置。若DATABASE_URL是相对路径，随新项目目录解析；若是绝对路径，请确认它仍指向你想使用的库。也可用`scripts/backup_database.py`先做一致性备份。
4. 按原启动方式运行`Start_GameReach.bat`或`bash scripts/run_demo.sh`，确认页面版本0.10.0。包内含前端产物，通常无需重新构建前端。
5. 新建一次研究，建议先选1款，确认你的网络下效果。旧失败报告是历史快照，不会因为升级自动变成成功。

无需你修代码、手写标签、整理715篇评论或重新申请密钥。若想提高每轮数量，才需要你决定可接受的耗时与调用预算：`.env.tag-budget.example`提供外部请求100、模型40、工具50、活跃900秒的可选配置。只修改对应预算字段后重启，不必改变密钥；这些是上限，不能保证一定推荐5–10款。
