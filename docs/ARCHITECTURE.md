# 架构与检索

GameReach 是本机单用户应用：React 页面 → FastAPI → 持久化 Engine → 白名单来源 / 模型。SQLite 保存业务数据与检索副本；没有独立搜索服务或向量数据库。

## 数据职责

| 层 | 用途 | 能否直接证明游戏事实 |
|---|---|---|
| Document | 不可变原文版本、来源、游戏 / 数据集、发表 / 修改时间、作用域 | 是事实核查的原始材料；自身不保证真实 |
| DocumentIndex | 当前版本、访问范围、撤销状态、哈希及索引版本 | 仅决定来源是否可用于当前判断 |
| Chunk / FTS5 | 最长 800 字符、约 120 字符重叠的检索片段，保留原文偏移 | 必须回到 Document |
| Span | 被实际引用的逐字片段及精确位置 | 用于检查引用存在与上下文 |
| Claim | 提取出的候选主张、逐项核验状态、支持 / 反对引用 | 仅 supported 且来源当前有效的结论参与画像 |
| FeatureAssessment | 带作用域的机制评估修订 | 当前有效修订参与确定性排序 |
| DnaSnapshot / Report | 某次探索的冻结结果 | 派生输出，不能当作独立来源 |
| MemoryIndex / 兴趣卡片 | 历史输入检索 / 可撤销的软兴趣 | 不进入游戏事实索引 |

## 检索路径

1. SQL 读取有效机制评估，明确缺口；已有事实可避免重复模型调用。
2. 按当前问题与缺口检索 FTS5。英文按词，中文按相邻双字切分；机制词表的中英文别名映射到同一索引词。
3. 在 SQL 中限制游戏、数据集、任务允许文档、访问范围、时间与作用域。返回后再校验全文 / 片段哈希。
4. 真实模型每批只看一款游戏，默认最多60条独立评论片段和3份说明片段；先保留目录 / 商店说明，评论按正面 / 负面 / 近期轮流选择，每个文档选一个最相关片段。既有评估单独标为背景。无词面匹配时可提供少量合格原文作有限阅读，不能据此断言机制不存在。
5. 新引用必须存在于实际送入模型的片段中，定位回原文的 start/end；核验器看引文前后各约 400 字符，避免再次漏掉文末。
6. 缺口仍在时由既有任务继续查资料。评论游标来自适配器响应，有限读取后续页；性能问题仍可按需查公告与补丁后评论。默认最多 2 次补查轮次，并受总调用与时间预算约束。

索引版本：`cjk-bigram-alias-1:800:120`；embedding 版本为 `none`。这是词面与机制别名检索，不能声称具备任意语义理解。SQLite FTS5 机制参考：<https://www.sqlite.org/fts5.html>。

## 失效与历史

同一来源的新版原文或关键元数据产生新 Document ID，旧版本停止进入当前索引，旧块移除；原始 Document / Span 保留。重放旧缓存不会把旧头版本重新激活。原文日期或修改日期超过 730 天时退出当前推荐；抓取时间不能把旧评论变新。无可靠日期明确为未知，此规则是保守工程策略，不证明 730 天内的观点仍适用。合成测试语料的日期不按真实时间淘汰。

撤销来源会移除其检索块及相应适配器缓存，使当前画像失效。历史快照保持原样，但若原引用或核验状态失效，重新排序会要求开始新探索，不用旧事实重新作当前判断。

更新 / 删除 Chunk 和 MemoryIndex 的 SQLite 触发器同步维护 FTS。历史输入查询前对任务原文哈希做增量核对；已删除或修改的输入不继续命中旧文本。索引重建保留来源的撤销和权限状态。少量已确认兴趣直接读取；当前输入和最新显式反馈不经相关性筛选，避免被旧记录挤掉。

这是回环网络上的单用户应用。`owner_id=local` 是本机所有者标记，检索测试也覆盖其他 owner 不可见；这不等于已经实现多用户认证或公共部署。

## 维护

先停止服务并备份，命令在 backend 目录运行：

```bash
uv run python ../scripts/rebuild_index.py --rebuild
# DOCUMENT_ID 用证据抽屉中的原始文档 ID 替换：
uv run python ../scripts/rebuild_index.py --revoke DOCUMENT_ID
```

这两个命令不调用模型或外部来源。撤销是停止当前使用，不是物理抹除历史引用。删除兴趣卡片也不是清空历史输入；删除导入只移除那份原始导入和未应用草稿，已确认卡片需单独删除。

## 保留的约束

真实来源 / 模型失败明确显示 partial 或错误；不回退 fixtures。报告由程序生成。硬要求不因资料不足而自动放宽；本地重排扩大平台范围或放宽硬条件需要明确新操作。人工动作有 action_id 和版本校验，取消 / 暂停在安全节点生效。来源内容不能授权任意 URL 请求、文件读取或命令执行。


## 0.8 推荐准入

`quality.py` 是唯一的卡片发布规则。快照仍保存全部候选便于冻结重排，报告 `results` 和 `/dna/rerank` 都只返回通过规则的卡片；其余以 `withheld_candidates` 的原因记录返回，不是推荐卡片。

任务锁定 `quality_policy`、采样上限和实际 `reviewed_document_ids` / `reading_windows`；采集、送读、复用和引用分别统计。来源撤销或替换后，复用阅读和文字引用均重新检查，不能只检查机制。

默认 scope 是主流程。已知默认模式别名归一为空 scope；实际限定难度 / 多人模式仍保留。带限制的体验文字在界面注明作用域，不能把它当作通用机制。

真实执行按游戏排列采集动作，每款提取后立即核验；卡片关键字段缺失时最多一次本地修订，再核验。预算不足不扩容，返回已完成卡片。评论适配器用正面 / 负面 Helpful 加 Recent 分层，去重、分页总上限和网络预算同时生效；采样设置纳入缓存键。Steam 个人库 Key 不发送给公开评论接口。
