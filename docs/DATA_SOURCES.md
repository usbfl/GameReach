# 数据来源 · 0.8

| 来源 | 用途 | 限制 |
|---|---|---|
| IGDB / Twitch OAuth | 真实目录、平台、类型线索、简介、商店链接、已核对外部 ID | 有限召回，最多20候选；目录标签本身不是机制证据 |
| Steam 商店说明 | 原始玩法说明；核对 coming_soon 和 Early Access，补充正式发售状态 | 固定 appdetails 接口，仅请求 IGDB 已核对的 AppID；不是承诺稳定的 Steamworks API，失败会保留未知 |
| Steam 玩家评论 | 玩法体验、优点、取舍、机制解读 | 默认最多120条，正面 / 负面 / 近期分层；去重后可能少于上限。单页≤100，按预算分页 |
| Steam News | 明确需要的公告补查、人工接管 | 开发者声明不自动证明玩家实际体验已改善；没有定时资讯监控 |
| 本地历史资料 | 已核验事实、已送读原文、引用位置 | 版本替换、撤销、过期后不继续作为当前结论；旧下载计数不能冒充阅读记录 |
| 合成 fixtures | 无密钥演示与回归 | 全部虚构。演示只需1条作者编写的评论，不使用真实模式的样本量下限；界面始终标注演示 |

体验评价当前仍来自 Steam。多条独立评论提供多个玩家视角，Steam 商店与 IGDB 补充玩法说明；不宣称已经获得多个评价平台、论坛或专业评测的交叉共识。其他商店通过 IGDB 的来源链接筛选，不冒充直接读取其玩家评论。

每条玩家评论尽量使用 API 返回作者 ID 对应的公开评论直达页；作者 ID 不额外存储为用户画像。缺少有效作者 ID 时仅有评论区链接，保留原始评论 ID 和逐字定位。未知来源链接、无法定位或语义未核验的引用不能支撑推荐。

每次提取最多送入60条独立评论的相关片段，此外保留最多3份目录 / 商店说明片段。不会把采集但未送给模型的评论计入实际送读数。分层样本和引用数均不等于全体玩家好评率。

硬限制未知也不能通过；无价格资料就不能宣称符合价格上限。找不到缺点不会编造：卡片暂缓推荐，范围记录中列出原因。所有18维不必填满，但本次关注的条件必须查清，默认至少3项有根据的机制。

真实连接与配置方法见 [CONNECTIONS.md](CONNECTIONS.md)，本轮真实测试见 [TEST_REPORT.md](TEST_REPORT.md)。
