## 发现的失败与解决过程

- 原版浏览器：12/24失败。包含默认目标5、合成候选/预算只形成部分结果却断言“研究完成”；`.warning`定位不唯一；依赖前一个测试留下草稿与旧label等。修正为读取实际任务/报告，严格校验achieved等于ID数量、met等于目标达成、界面状态等于后端状态；没有把任意终态当成功。
- 新版首轮浏览器24通过6失败：进一步暴露旧引用点击落到介绍而非评论、动态卡片确认后定位丢失、待调查诊断断言过期。改为准确定位并比较后端诊断。下一轮因同时启动两套CJS测试入口互相清理文件，出现15通过5失败10未执行；改为串行完整执行，最终30通过。
- 新增后端首轮22通过1失败：测试在create_app之前修改fixture标签，启动重载覆盖测试输入。改为启动后设置固定输入，原断言保留。
- 最终配置检查曾1失败278通过：动态提示改写遗漏旧断言要求的“不足3款”。恢复包含实际配置数量的准确提示，未改旧断言，最终279通过。
- 截图复核发现原有需求摘要浅色面板继承浅色文字，对比不足；改为现有深色主题配色，重新生产构建与完整浏览器验收。
- Ruff初次7处：含所改文件内原有单行if格式与2个未使用import；格式化相关文件并移除未用import，最终通过。
- 原版HTTP首次独立进程网络隔离导致连接拒绝；改用同一运行单元启动子服务并禁代理，实际HTTP成功。正式smoke脚本内置隔离子服务。
- 升级检查首次把API展示字段与原始存储对象全等比较导致断言不成立。分开检查存储精确值和所有原API字段，均通过；未修改数据以通过断言。
- uv离线锁刷新因缓存缺解析元数据失败；普通锁刷新成功，仅项目版本更新，依赖版本未改。

中间失败日志保留，不以最终绿色掩盖过程；`iteration_*` 等文件为迭代结果，最终状态以 `*_final` 和本表为准。
