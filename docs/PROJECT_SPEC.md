# 当前产品边界 · v0.11.0

本文件是当前规格；v0.10.2 原文保存在 `history/PROJECT_SPEC_0102.md`。详细实现与排序公式见 `CHANGES_011.md`。

## 兴趣画像

沿用原 interests/player 和64标签。成员身份合并后形成游戏—主题多对多关系，每个主题只计同一游戏一次；同一游戏可出现在不同卡片。默认每卡3–7款、最多6卡，配置可调整。游戏时长只作为有上限的关注线索，负面/排除反馈优先，不因收藏或高时长返回正向分组。目录/个人分类不冒充评论核验；已有 DNA 只做语义明确、来源有效的保守投影。不为库存新增逐款评论研究流程。

标题、相关游戏和概括保持原结构。支持成员、标题、概括编辑与确认/删除。旧确认内容不自动改写；无资料的游戏保留待归类。同义主题合并，内容相同的泛化分组抑制，但独立玩法可以共享成员。主题级增量缓存不会把一张卡片已用游戏从其他主题移除。

## 本次条件

默认自动解析；可先调用 `/api/tag-intent-preview`，前端编辑后通过 `confirmed_conditions` 提交完整最终快照。标签复用正式64项；方向、1–3重要度、软偏好/硬条件可编辑。未映射表达保留任务级 custom，可修改、确认、忽略。没有可靠映射的自定义条件不能伪造平台召回或支持证据。

最终人工快照 > 本次自然语言明确输入 > 主动附加历史卡片。未附加历史不注入任务；同标签多张卡片不能累计放大权重。卡片推断不能变成硬条件。默认状态不会强制每次人工确认。预览结果绑定输入/附件/数据集并带入预算，改输入或附件会失效。

## 推荐与研究

仅本次关注点参加匹配及补查。事实条件和用户明确的玩法必要条件有 pass/fail/unknown 三态；未知不进入已确认组，失败排除。软偏好未知不是不匹配，也不声称已满足；主要理由有可追溯支持时允许部分匹配。无已核验正向依据不得只靠口碑凑推荐数。

排序 `focus-rank-2` 使用已知加权表现、饱和的已核验权重/独立支持奖励及冲突惩罚。coverage 保留诊断，不乘入分数。游戏不相关维度不参与排序、不触发补查。结果主区域呈现支持当前需求的理由、重要取舍和硬约束未知；其他证据/未知折叠。介绍和总体口碑缺失本身不阻止有依据的部分匹配。

保留完整评论样本、好评/差评/近期分层、作者/正文去重、全文分批和独立语义核验。引文位置正确仍须语义支持；没有提及不代表机制不存在。优先补玩法硬条件与当前最高重要度维度的未知/冲突，支持足够且无可行动关键缺口时提前停止。平台/语言未知不会通过刷评论伪造确认，当前仅沿用既有事实来源能力。

## 基础设施与兼容

保留 Engine/SSE/预算/人工节点/历史/导出，以及快速、均衡、扩大三档、广召回窄调查、来源缓存和已核验批次缓存。完整正文未纳入分析会明确计数，不截断冒充全文。

预览和研究遵守现有调用上限；单纯调整标签权重在冻结证据上本地重排，新任务的核验缓存键也不依赖权重。新增关注点、改硬条件/范围或来源过期触发适用性检查。旧缓存因协议升级可能首次失效，但不删除历史报告。

新界面使用 `/api/tag-research`；`/api/research` 默认旧 DNA 协议保持兼容。旧机制门槛仅作用于旧协议，不主导新入口。无 SQL 表/列变化，现有 Alembic 初始化仍可运行；新增 JSON 字段有默认值，不批量重写用户数据。

fixtures/mock 与 live 分离；真实服务失败不静默切换演示。不自动修改密钥、购买、发布或启用付费服务。运行时完整评价源仍为 Steam，其他商店经 IGDB 目录召回；不宣称全部论坛已接入。
